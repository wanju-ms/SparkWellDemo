## WEB-TODO-014 确认删除与最后一条记录

验证：删除需要确认，取消不改变数据；所有状态都能单条删除，最后一条删除后显示空列表。

前置：待删除功能交付，在空的专用服务中准备以下三条记录，记录其内容和创建时间。

| 任务 | 状态 | 截止时间 |
| --- | --- | --- |
| `QA-WEB-014-未完成` | `Incomplete` | 不设置。 |
| `QA-WEB-014-已完成` | `Completed` | 昨天 12:00。 |
| `QA-WEB-014-已过期` | `Overdue` | 以 `Incomplete` 保存昨天 12:00 的截止时间，由服务转为过期。 |

来源：[Todo App：删除](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Service：删除契约](../../../artifacts/sparks/todo-service.md#operations)、[Todo Item：状态](../../../artifacts/sparks/todo-item.md#status-changes)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 对未完成记录打开删除入口，先不确认。 | 显示待删除任务的名称，并要求确认；列表中仍有该记录。 |
| 2 | 在 Network 中清空记录，然后取消删除并点击 `Reload todos`。 | 取消不发出删除请求；成功刷新后，三条记录仍在，内容和创建时间不变。<br>正常的列表读取请求不算删除请求。 |
| 3 | 再次删除未完成记录并确认，等待成功结果。 | 只移除选中的记录；另外两条的内容、状态和创建时间不变。 |
| 4 | 对已完成、已过期记录分别执行步骤 1 至 3，每次只处理一条。 | 两种状态均可取消或确认删除；不存在状态限制或批量删除。<br>最后一条成功删除后显示 `No todos yet`。 |
| 5 | 点击 `Reload todos`，再重新加载页面，API 保持运行。 | 集合仍为空，不重新出现已删除记录。<br>本功能不提供撤销或回收站。 |

## WEB-TODO-015 删除中禁止重复操作

验证：尚未确认删除时保留列表项，禁止重复删除和编辑该条。

前置：待删除功能交付，准备无截止时间的 `QA-WEB-015-等待` 和 `QA-WEB-015-保留`。
关闭其他操作同一记录的客户端，按公共说明启用延迟配置。

来源：[Todo App：删除等待](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Expiration Sync：确认删除与刷新](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 对 `QA-WEB-015-等待` 确认删除，连续点击确认两次。 | 显示删除进度，不因点击就移除记录，不发起重复删除。 |
| 2 | 在删除尚未确认时尝试再次删除或编辑该条；若确认界面遮挡列表，检查它没有提供绕过等待状态的操作。 | 同一记录不能重复删除或进入编辑，列表保留最后确认的状态。 |
| 3 | 等待删除被确认，恢复正常网络并重新加载。 | 目标记录消失，保留记录不变；等待状态结束。 |

只在删除请求或已接受的完整列表尚未确认记录消失时检查步骤 2。
如果等待删除响应时，另一份成功的完整列表先确认记录已不存在，移除记录是允许的。
若延迟不足以观察等待窗口，重新准备独立数据；不要把没观察到当作保护已通过。

整个过程保持 API 运行。

来源：[Todo App：删除失败](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Service：删除与重试](../../../artifacts/sparks/todo-service.md#operations)、[Todo Expiration Sync：刷新失败不是删除证据](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 启用 Todo 请求阻止，再确认删除目标；在 Network 中确认删除请求被浏览器阻止。 | 显示错误，允许重试或取消；列表仍保留目标，不能显示删除已成功。 |
| 2 | 取消本次删除，恢复正常网络，点击 `Reload todos`。 | 成功读取后，记录仍存在且内容、创建时间不变。 |

## WEB-TODO-017 重复删除已不存在的记录

验证：另一页面已删掉目标后，针对同一 ID 的删除仍返回成功，不影响其他记录。

前置：待删除功能交付，两个 Web 页面 A、B 连接同一专用服务，均显示 `QA-WEB-017-重复` 和 `QA-WEB-017-保留`。
额外执行条件：需要一种已记录的手工控制方式，暂缓 B 的列表请求，但允许 B 的删除请求正常发送。
当前只有阻止全部 Todo 请求的说明，不能满足此条件；本例还需补充环境支持，不能靠快速切换页面抢时序。

来源：[Todo Service：删除不存在的 ID](../../../artifacts/sparks/todo-service.md#operations)、[Todo App：删除结果](../../../artifacts/sparks/todo-app.md#deleting)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 使用就绪的控制方式暂缓 B 的列表请求，在 B 打开目标的删除确认，暂不确认。 | B 保留该目标的 ID，没有发送删除请求。 |
| 2 | 在 A 删除同一目标并等待确认成功。 | A 移除目标，保留记录不变。 |
| 3 | 回到 B，确认仍针对原 ID 的删除。 | 即使目标已经不存在，服务也确认成功；B 移除目标，不把不存在显示成无法完成删除的错误。 |
| 4 | 恢复 B 的列表请求，两边均刷新。 | 目标均不存在，保留记录未变。 |

若 B 已先通过刷新移除目标，记录本次没有构造出重复删除，不算步骤 3 已验证。
结束后解除请求控制并关闭 B。

## WEB-TODO-018 编辑中的记录被另一页面删除

验证：刷新失败不会误判删除；成功刷新确认目标消失后，禁止保存但保留草稿供复制，关闭时不自动新建。

前置：待删除及已删除编辑目标处理交付，两个 Web 标签页 A、B 连接同一专用服务，均显示无截止时间的 `QA-WEB-018-原记录`。

来源：[Todo App：结果处理](../../../artifacts/sparks/todo-app.md#editing-and-saving)、[Todo Editor：已删除草稿](../../../artifacts/sparks/todo-editor.md#validation-and-saving)、[Todo Expiration Sync：删除通知](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 在 A 编辑目标，将任务改为 `QA-WEB-018-A草稿`，描述改为 `保留以便复制`，截止时间设为明天 14:30，不保存。<br>仅在 A 的 DevTools 中启用 Todo 请求阻止。 | 草稿尚未写入，B 仍显示原记录。 |
| 2 | 在 B 删除原记录并确认成功，然后返回 A，等一次列表刷新失败。 | A 显示刷新错误，保留最后确认的列表和草稿；不能仅凭刷新失败就提示目标已删除。 |
| 3 | 解除 A 的请求阻止，等待成功的完整列表刷新。 | A 从列表移除目标；编辑器显示目标已删除，Save 和保存重试不可用。<br>弹窗保留任务、描述和明天的截止时间，没有自动关闭或清空草稿。 |
| 4 | 查看草稿，并将任务和描述复制到普通文本编辑器核对。 | 文本仍可读取和复制，内容与步骤 1 一致。 |
| 5 | 关闭编辑器，重新加载 A，再打开 `New todo`。 | 已删除记录和草稿均未变成新记录；新建输入恢复默认值。<br>取消新建，关闭 B，并恢复网络设置。 |

本例验证通过完整列表确认删除，不覆盖更新先返回 not-found 或旧保存结果晚到的路径。
这些时序需要额外的人工请求控制，不能把本例当作它们已经通过。
