- 预计用时：就绪后约 15–25 分钟，不含首次安装和额外网络控制准备。
- 状态：三条用例均待实现、未执行；当前 [iOS 列表](../../../src/ios/TodoApp/ContentView.swift)尚无删除入口。

删除入口、确认提示和错误提示的文案尚未确定。
用例以“删除入口”“确认删除”“取消删除”表示设计动作，不假定有滑动删除手势或特定图标。
交付后先核对实际入口、服务删除能力和提示，再执行。
多端正在编辑时被删除的场景见[跨平台套件](../cross-platform/README.md)，不在这里重复。

## 公共准备

按 [README 的 iOS 说明](../../../README.md#ios)安装并运行 TodoApp，连接独立的测试 API。
记录应用构建、iOS 版本、设备或模拟器、本机时区和语言区域。
基础用例使用现有项目支持的 iOS 26.5+ 环境；本组不证明其他版本的兼容性。
不同用例使用独立任务名称，不能依赖上一条用例的执行结果。

点击 `New todo`，输入 `Task` 和 `Description`，在 `Status` 中选择状态，再点 `Save todo` 准备记录。
不需要截止时间时保持 `Deadline` 关闭。
需要日期时间时开启 `Deadline`，通过 `Due at` 选择器输入设备本地时间。
列表的编辑按钮对应 `Edit todo`，工具栏刷新按钮对应 `Reload todos`。

### 网络条件

断网用例使用真机，初始通过 Wi-Fi 连接 Mac 上的专用 API。
根据根 README 配置 Mac 的局域网地址、`HOST=0.0.0.0` 和本地网络权限。
发送删除前，在 iOS 设置中开启飞行模式并确认 Wi-Fi 也已关闭，确保设备没有连接测试 API 的通道。
不要停止或重启 API；断开的是客户端网络，不是数据服务。
恢复时关闭飞行模式并重新连接原 Wi-Fi，再回到 TodoApp。
仅有模拟器时，不要把 Mac 断网当成模拟器无法访问本机 API 的证据；未能构造断网条件的用例记为受阻。

等待保护需要已确认的手工网络控制，能够延迟该应用的删除提交或响应，并观察请求何时完成。
当前项目未记录这样的原生端控制工具；IOS-TODO-003 需补齐操作方法后执行。
不调用自动化测试专用接口，也不编写测试脚本。

## 清理与边界

每条用例结束后恢复真机网络或解除延迟控制。
删除功能尚未交付时，需要清空数据只能重启专用 API；这会清空整个集合，不得对共享服务这样操作。
执行用例期间 API 应一直运行，以免把重启清空误判为删除成功。

本组不覆盖 iOS 全量新建、编辑、校验、辅助功能或设备组合。
删除重复请求、not-found 更新、丢失删除响应，以及删除后晚到的保存和刷新结果需要补充请求时序控制；基础流程不能证明这些路径正确。
服务后台检查与删除的内部并发也未在本组直接验证。
长期持久化仍未交付，不要求 API 重启后保留记录。
执行结果由 QA 另行记录，本套件不预填通过或失败。
