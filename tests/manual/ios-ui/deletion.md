## IOS-TODO-001 确认删除与最后一条记录

验证：取消不删除，所有状态都能确认删除，最后一条成功删除后显示空列表。

前置：待删除功能交付，在空的专用 API 中通过原生编辑器准备三条记录，记录其内容和创建时间。

| 任务 | 状态 | Deadline 与 Due at |
| --- | --- | --- |
| `QA-IOS-001-未完成` | `Incomplete` | `Deadline` 关闭。 |
| `QA-IOS-001-已完成` | `Completed` | 开启 `Deadline`，设为昨天 12:00。 |
| `QA-IOS-001-已过期` | `Overdue` | 以 `Incomplete` 保存昨天 12:00 的截止时间，由服务转为过期。 |

来源：[Todo App：删除](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Service：删除契约](../../../artifacts/sparks/todo-service.md#operations)、[Todo Item：状态](../../../artifacts/sparks/todo-item.md#status-changes)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 对未完成任务打开已交付的删除入口，暂不确认。 | 提示中显示选中任务的名称，要求确认；记录仍保留。 |
| 2 | 取消删除，点击 `Reload todos`。 | 成功读取后，三条记录的内容、状态和创建时间未变。 |
| 3 | 再次对同一记录确认删除，等待成功结果。 | 只移除该记录，另外两条不变。 |
| 4 | 对已完成、已过期记录分别重复步骤 1 至 3，每次只处理一条。 | 两种状态也能取消或确认删除；最后一条删除成功后显示 `No todos yet`。 |
| 5 | API 保持运行，关闭并重新打开 TodoApp，等待加载成功。 | 集合仍为空，已删除记录不再出现；没有撤销或回收站流程。 |

## IOS-TODO-002 断网删除后的取消与重试

验证：设备在提交前断网时不丢失记录，取消和恢复后的重试均有清楚结果。

前置：待删除功能交付，使用[网络条件](README.md#网络条件)中所述真机，准备无截止时间的 `QA-IOS-002-重试`，记录内容和创建时间。
仅有模拟器或不能确认 API 连接已断开时，本例受阻。

来源：[Todo App：删除失败](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Service：删除](../../../artifacts/sparks/todo-service.md#operations)、[Todo Expiration Sync：失败刷新](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 在发送删除前按公共说明断开真机网络，回到应用并确认删除目标，等待请求报错。 | 提示删除失败或无法确认结果，允许重试或取消；不能把网络错误当成删除成功，最后确认的记录仍保留。 |
| 2 | 取消删除，恢复原 Wi-Fi，回到应用并等列表成功刷新。 | 原记录仍在，内容和创建时间不变。 |
| 3 | 再次在提交前断网并确认删除；报错后恢复网络，使用重试动作。 | 成功确认后目标从列表消失，不影响其他记录。 |
| 4 | 点击 `Reload todos`，再重新打开应用。 | 目标不再出现，没有残留的删除等待或错误状态。 |

恢复网络之前不要重启 API。
本例不覆盖服务已提交删除但响应丢失的情况。

## IOS-TODO-003 删除中禁止重复操作

验证：删除等待期间不能重复提交或编辑该条，确认前不提前移除记录。

前置：待删除功能交付，准备无截止时间的 `QA-IOS-003-等待` 和 `QA-IOS-003-保留`。
额外执行条件：需按[网络条件](README.md#网络条件)补充人工可用的请求延迟和观察方式，当前不能直接执行。

来源：[Todo App：删除等待](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Expiration Sync：确认与旧结果](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 使用就绪的控制方式延迟目标的删除请求，对 `QA-IOS-003-等待` 连续确认两次。 | 显示进度，不重复提交；在删除尚未被确认时保留记录。 |
| 2 | 在等待状态尝试再次删除或编辑同一条记录；若确认界面遮挡列表，检查它没有绕过等待的操作。 | 重复删除与编辑均不可执行。 |
| 3 | 释放延迟，等待删除成功，解除控制并点击 `Reload todos`。 | 目标消失，保留记录未变，等待状态结束。 |

如果成功的完整列表先确认目标已不存在，可以先移除记录，不必等删除请求自己的响应。
没有观察到真实等待窗口时，不把该项记为通过。
