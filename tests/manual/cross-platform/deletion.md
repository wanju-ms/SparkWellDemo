## CROSS-TODO-001 另一端删除后保留草稿

验证：一端删除记录后，另一端通过刷新停止保存该记录，但不丢弃正在编辑的内容，也不自动另建记录。

前置：两端连接同一个专用 API，按以下两种方向各执行一次，每次准备独立的无截止时间记录，描述为 `原描述`。

| 方向 | 观察端 A | 删除端 B | 已保存任务 |
| --- | --- | --- | --- |
| iOS 删除 | Web | iOS | `QA-CROSS-001-Web草稿` |
| Web 删除 | iOS | Web | `QA-CROSS-001-iOS草稿` |

来源：[Todo App：删除](../../../artifacts/sparks/todo-app.md#deleting)、[Todo Editor：已删除目标](../../../artifacts/sparks/todo-editor.md#validation-and-saving)、[Todo Service：共享数据](../../../artifacts/sparks/todo-service.md#saved-data)、[Todo Expiration Sync：删除同步](../../../artifacts/collaborations/todo-expiration-sync.md#polling-and-editing)。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 两端加载本方向的已保存记录，在 A 打开编辑器。<br>给任务名追加 `-未保存`，描述改为 `只在A保留`，截止时间设为明天 14:30，选择 `Completed`，不保存。 | A 的草稿改变，但 B 仍看到已保存的原任务、原描述和 `Incomplete`。 |
| 2 | 在 B 对原记录打开删除入口，核对任务名并确认，等待删除成功。 | B 移除目标；确认提示使用已保存的任务名，不使用 A 未提交的名称。 |
| 3 | 让 A 保持或返回前台，等待之后一次成功的完整列表刷新。 | A 列表移除目标；编辑器显示目标已删除，Save 和保存重试不可用。<br>A 的弹窗仍在，任务、描述和明天的截止时间保留，不自动关闭或清空。 |
| 4 | 在 A 查看草稿，并将任务和描述复制到普通文本或备忘录应用核对。 | 草稿可读、可复制，文本与步骤 1 一致。 |
| 5 | 在 A 关闭编辑器，重新打开新建入口，再取消新建；两端刷新列表。 | 新建使用默认值，不沿用已丢弃的草稿。<br>两端都没有恢复原记录，也没有自动创建追加 `-未保存` 的记录。 |

Web 与 iOS 的弹窗、控件和复制方式可以不同，业务预期相同。
保持 API 运行，等待成功读取作为判断依据，不把断网、读失败或尚未完成的刷新当作删除确认。
