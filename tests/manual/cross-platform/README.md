# Todo：跨平台删除手工测试

## 范围

- 被测对象：`web-ui` 和 `ios-ui`，连接同一个真实 Todo API。
- 本次只覆盖删除发生在另一端时，正在编辑的一端如何保留草稿并停止保存。
- 状态：待实现、未执行；两端尚未提供删除入口，不能按当前构建直接执行。
- 预计用时：两种方向合计约 10–15 分钟，不含首次安装；仅为执行估计。

## 公共准备

按 [README](../../../README.md)启动独立的 API、React Web 和原生 TodoApp。
Web 使用桌面 Chrome，iOS 使用项目支持的模拟器或真机；记录两端版本、语言区域和时区。
模拟器可访问 Mac 上的默认 API；真机使用 Mac 的局域网地址，并按 README 设置本地网络权限。
确认两端指向同一个 API 进程，而不是两个空的独立服务。
执行中不要停止或重启该进程。

在操作端点击 `New todo`，填写本例指定任务和描述，保持 `Incomplete`，不设置截止时间，点击 `Save todo`。
在观察端点击 `Reload todos`，确认看见同一条已保存记录。
Web 用 `Due at` 输入截止时间，iOS 先打开 `Deadline`，再用 `Due at` 选择器输入。
两端都使用各自的 `Edit todo`、`Save todo` 和 `Cancel` 动作。
删除动作的入口与文案仍待实现，本例不假定 Web 按钮或 iOS 滑动手势。

## 清理与边界

每种方向使用独立数据，关闭用例留下的弹窗和额外客户端。
需要清空数据时，只在用例结束后重启专用 API，不对共享服务重置。

本例通过成功的完整列表获知删除，不要求两端在精确的秒数内同步，也不测试推送通知。
不覆盖延迟保存或冲突结果重新插入记录、更新先返回 not-found、服务内部并发或删除响应丢失。
这些路径需要可记录请求顺序的人工控制方式，不能从正常刷新推断它们已经正确。
执行结果由 QA 另行记录，不预填通过或失败。
